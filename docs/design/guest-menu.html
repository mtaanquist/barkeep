The menu, three seconds after the QR code

Built only from tokens.css and the component kit. Mobile at 390, desktop at 1280, both schemes. The native <select> is gone: filtering is a sticky chip rail you can read while scrolling, with a sheet behind it for the full list. Danish throughout; English in the note under each block.

Mobile · 390px

Filtering. A sticky chip rail replaces the select. The rail scrolls horizontally, always shows the current filter first, and every chip carries its count — so a guest sees what is on offer without opening anything. The leading Filtrér button opens a bottom sheet with the full list (categories, then base spirits) when the rail isn't enough. Nothing navigates away: the sheet slides over the menu, the menu stays scrolled where it was. Chips: 44px tall, 12px gap, radius-full; selected is text/text-inverse, the rest surface-raised/border.
Touch targets. Order 64px (spacing-hit-lg), recipe / star / header actions / chips / sheet rows all 44–56px, minimum 8px apart. One column, not two: a card at 358px wide can carry a real photo, a 21px name and a 64px button — a two-up grid can carry none of them at arm's length in a dim room.
Surprise me. A dashed border-strong strip under the rail with a dices icon and a mono kicker. It has the width of a primary action but none of the fill — it reads as a raffle ticket stapled to the top of the menu, and it never competes with an Order button, because it never uses accent.

The one-order rule, explained before the tap — not after. Three things carry it at once, so no guest has to discover it by failing: (1) the live-order card is pinned under the header and states the condition in words — "Du kan bestille igen, når den er hentet."; (2) every Order button is replaced, not greyed — the label itself becomes "Én bestilling ad gangen" with a lock icon, so the reason is legible at arm's length in a dim room; (3) the card's photo and description drop to 55%/75% opacity while the name stays at full contrast, so the whole menu reads as "browsable, not orderable". Tapping a locked button does nothing — no alert, no toast — and instead scrolls the live-order card into view and pulses its border over duration-quick. When it flips to ready (third dark frame) the live card becomes the only accent fill on the screen and the copy switches to an instruction: "Hent den i baren. Spørg efter Kasper."

Drink card · every permutation

The card is one object with three optional parts (photo, description, recipe) and two switches (favourite, orderable). Photos are cropped to a fixed 16:9 box with object-fit:cover, so a portrait phone snap and a wide flash photo occupy identical space. No photo is not an empty box: the media block becomes the drink name at text-display on surface-sunken, left-aligned and allowed to wrap to three lines — a half-photographed menu still reads as one deliberate grid. The action strip is always the last 64px of the card, so the thumb finds it at the same place on every card whatever is missing above it.
