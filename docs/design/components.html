Barkeep · Back Bar · component kit

Components

Every specimen below is drawn from tokens.css only — the light column inherits the light variables, the dark column overrides the same names, and nothing in a component knows which one it's in. Danish is set in the live label with the English underneath, so you can see the layout hold at the longer length. Icon slots name the lucide icon rather than drawing it. Four tokens were added to the sheet to build this kit: danger-*, disabled-*, overlay, skeleton / skeleton-highlight.

Buttons

Tokens — primary: text fill + text-inverse label; secondary: surface-raised + border + text; ghost: transparent + text; danger: danger + danger-contrast. Hover swaps to *-hover, active adds border-strong inset, focus-visible is shadow-focus, disabled is disabled-bg / -border / -fg. All radius radius-md, all duration-instant.
Touch target — 44px minimum anywhere; spacing-hit 56px for every bartender action (wet hands, arm's length); spacing-hit-lg 64px full-width for the guest Order button. The accent is never a button fill except the guest Order button — it means READY everywhere else, and two meanings would cost more than it buys.

Form fields

Tokens — field: surface-raised on border, text text, placeholder text-muted; label text-label in text; help text-body-1 in text-muted; focus border-strong + shadow-focus; error border danger with message in status-rejected-fg.
Touch target — every field is 48px on the bartender side and spacing-hit 56px on the guest side. The <select> is a real native select: appearance:none plus token background, token border and a chevron drawn in the field's own padding — the OS list still opens, so it stays usable one-handed and keyboard-accessible. Error state is never colour alone: the border changes weight, and the message carries an alert-circle.

Card — one surface, two jobs

Tokens — surface-raised + 1px border + radius-md + shadow-flat, sitting on surface-sunken. Sections inside are separated by a border-width-hair rule, never by a nested card. A drink card is the same object as a settings panel with a media block bolted on top and an action strip below.
Touch target — the whole drink card is tappable at ≥88px; its action strip is spacing-hit-lg 64px. Settings rows are 56px. No photo is a designed state, not a fallback: the media block becomes the drink name at text-display on surface-sunken, so a menu of half-photographed drinks still scans as one grid.

Status pill & count badge

Tokens — pill: status-{new|accepted|rejected|ready|processed}-{bg|border|fg}, text-caption, radius-sm. Count badge: text fill / text-inverse label at rest, accent / accent-contrast only when something is ready and waiting, radius-full.
Touch target — none; both are read-only. They never carry the only copy of a state: the pill sits next to a name, and the rail's left bar repeats the same status in shape.

Tabs — bartender top-level navigation

Tokens — bar on surface with a bottom border; rest label text-muted, selected label text with a border-width-strong border-strong underline; hover surface-sunken; focus shadow-focus. Badge tokens as above.
Touch target — 56px tall (spacing-hit), minimum 72px wide. Overflow: the row scrolls horizontally with momentum and never wraps, collapses into a menu, or truncates a label — a hidden tab is a tab the bartender won't find. The selected tab is scrolled into view on mount, and a surface-to-transparent fade on the trailing edge signals there is more. Danish "Indstillinger" is the width driver, so the row is designed at Danish and simply has slack in English.

Dialog

Tokens — backdrop overlay; panel surface-raised + border + radius-lg + shadow-float; header/actions divided by border rules; title text-display, body text-body in text-muted. Enters at duration-enter.
Touch target — actions 56px (spacing-hit), close button 44px. Dark is not a tinted light dialog: the panel goes up to surface-raised while the backdrop goes to 72% black, so the dialog is the lit object in the room rather than a white rectangle fired into someone's eyes at a party. Destructive action is on the right and is the only danger fill on screen.

Connection banner & empty state

Tokens — banner: status-rejected-bg / -border / -fg with a border-width-rail left bar, retry as a secondary button, dismiss as ghost. It reuses the rejected role rather than a new "warning" hue — one red, two contexts. Empty state: text-muted icon on surface-sunken, headline text-heading in text, one line of text-body in text-muted.
Touch target — retry and dismiss 44px each, 8px apart; the banner is sticky under the tabs and never covers the first ticket. A lost connection is stated in words, not by a silent icon — the bartender must know the rail is stale.

Loading — drink grid skeleton

Tokens — card chrome unchanged (surface-raised, border, radius-md); the blocks inside are skeleton pulsing to skeleton-highlight over duration-enter×5 with ease-standard. Opacity pulse, not a sweeping gradient: a shimmer travelling across a dark screen at a party reads as a glitch.
Touch target — none; skeleton cards are inert and aria-busy. They occupy the exact geometry of the real card, so nothing moves under a thumb when the data lands. Three cards, always — enough to read as a grid, few enough not to promise a menu size we don't know yet. Reduced-motion drops the pulse and holds skeleton flat.
