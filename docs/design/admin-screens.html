The rest of the bartender’s app

Menu, drink form, categories, settings, analytics, QR. These are done between rushes, sitting down — so they get the same rails, the same 56px controls and the same one-primary-per-view rule as the queue, and nothing new. The only genuinely new problem here is the QR code in dark mode; it is solved at the bottom.

Drink menu · 1280 light, 390 dark

A list, not a grid: the useful columns are stock and category, and rows compare better than cards. Out of stock is a state, not an error — the row keeps its ink but the thumbnail desaturates and the name takes a muted mono UDSOLGT tag; no red, because nothing is wrong. Row actions repeat the queue’s grammar: a 56² outline square for delete on the far right, edit as the row itself (whole row is the target, chevron at the end). On 390 the same rows lose the category column and gain a 64px floating add button, bottom-right, text fill with shadow-float — the only floating element in the product. It sits 16px above the shell's queue bar, never over it: the bar is 64px of fixed chrome at the foot, so the FAB's bottom offset is 80px, not 16px. The mock below shows the drink menu in isolation; inside the shell it rides that much higher.

Add / edit drink — the longest form in the app

Structure comes from three named sections separated by full-bleed rules — Det gæsten ser, Opskrift, Placering & lager — in that order, because it is the order someone thinks in: what it’s called, how it’s made, where it lives. Each section has a one-line mono kicker and never more than four fields. The markdown editor is the only field that grows; it is monospaced, 17px, with a plain toolbar and a live-preview tab rather than split panes, because at 640px of form width a split pane gives you two unreadable columns. Save is a sticky 64px bar at the foot: Gem filled ink on the right, Annullér as text on the left, delete banished to the section footer where it can’t be reached by accident.

Categories & settings

Categories are a reorderable list with a 56px drag handle on the left — the handle is the only place the row can be grabbed, so a scroll gesture never becomes a reorder. Rename is inline (the row becomes a field), delete asks what to do with the drinks inside and offers a target category; a category holding drinks can never be deleted silently. Settings is three groups of at most three fields on one column, 640 wide: nothing here is used twice a night, so it gets no dashboard treatment and no shortcuts.

Analytics, and the QR code problem

Analytics is a curiosity read once at the end of the night, so it is set like a page, not a dashboard: four stat cards in plain hairline boxes, one ranked list, one list of sentences. Bars are text at 100% for the leader and the same ink at lower opacity below — one colour, so rank is read by length, and no legend is needed. No accent anywhere on this screen: nothing here is urgent.
The QR code is the one place dark mode must be overridden, and it is overridden deliberately, not accidentally. A QR needs a light quiet zone and high contrast to scan; inverting it hurts scan rates on older phone cameras, and printing it from a dark screen wastes ink. So the code sits on a fixed white card — literally paper — inside the dark dialog, with its own 24px quiet-zone padding, and that card is the exact bitmap the download button exports. The rest of the dialog stays dark, which makes the white card read as an object you can hold out to someone rather than a bug. The link row underneath keeps normal dark tokens, because a URL is text, not an optical target.

The drink form's other two states — empty, and mid-upload

Filled is shown above. Empty is not a blank version of filled — it is the same three sections in the same order, but only the first is expanded; Opskrift and Placering & lager collapse to a labelled row with a mono VALGFRI / 1 PÅKRÆVET marker, so a bartender adding a drink at 19:30 can type a name and save in fifteen seconds. Nothing is disabled and nothing is hidden; the form simply doesn't pretend all eleven fields are equally urgent. Mid-upload is the one place a progress indicator exists on the admin side, and it is a determinate 4px rule under the thumbnail, never a spinner — phone uploads over a house wifi take long enough that "how much longer" is a real question. The crop step follows automatically, in the same slot, and is the only modal in the form: it takes over because there is exactly one decision and no way to be doing something else.

Two corrections these screens inherit from the shell

The floating add button stays, and moves up. The shell's queue bar owns the bottom 64px and may never be covered, so the FAB's offset becomes bottom:80px; right:16px — clear of the bar, still thumb-reachable, still the only floating element in the product. It is also the reason the queue bar loses its chevron on the drink menu: two stacked affordances in one corner is one too many.
The form is a sub-screen, not a card. Its header is the shell's: labelled back to Drinks, the drink's own name as the title (“Ny drink”, muted, when there isn't one yet). The three sections, the 640px column and the sticky save bar are unchanged — only the container and the way out.
